# 数据库分析报告

### 一、用户分析

- 总注册用户数：**89 人**
- 复购率：**11.24%**
- 平均客单价：**$1473.09**

**分析说明**：
89 位注册用户中，仅少部分用户产生多次下单行为，复购率 11.24%，用户整体粘性偏低；平均客单价达到 1473.09，存在大金额订单拉高整体均值。8 月新增 58 人，9 月新增 31 人，注册用户呈回落趋势，可关注注册渠道以及注册接口是否存在异常。

### 二、商品分析

- 最畅销商品：**MacBook（255 件）**
- 销售额最高分类：**Desktops（$128212.00）**
- 主流价格区间：**$100‑200**

**分析说明**：
MacBook 为平台爆款商品，销量远高于其他商品；销售额主要来自 Desktops、Laptops & Notebooks 两大电脑分类。商品数量最多集中在 100‑200 价格区间，是平台主力定价档位；同时存在少量高价商品拉高整体客单价。

### 三、订单趋势

- 近 30 天日均订单量：**10.5 单**
- 订单量最高峰日期：**2026‑08‑26（28 单）**
- 销售额最高月份：**2026 年 08 月（$236134.80）**

**分析说明**：
近 30 天订单波动明显，8‑26 到达订单峰值 28 单，部分日期订单量偏低。8 月整体订单、销售额显著高于 9 月，业务流量存在明显月份差异。版本上线前后可以通过该维度做指标对比，快速识别订单暴跌等线上故障。

### 四、数据一致性

- 订单金额与明细一致：**❌ 发现 25 条异常订单**

**校验说明**：
校验发现共 25 笔订单，订单主表`total`总金额与订单明细汇总金额不相等，每笔订单均存在金额差异。说明下单、保存订单业务逻辑存在缺陷，页面展示订单金额和底层数据库明细数据对不上，属于严重隐性数据 BUG，需要复现排查下单、改价接口。

### 五、整体分析总结

1. **用户层面**：注册用户 89 人，但复购率偏低，多数用户只浏览不下单或者仅下单一次；8 月注册量高于 9 月，需要关注新增用户下降原因。高额订单拉高平均客单价，消费两极分化明显。
2. **商品层面**：营收高度依赖 MacBook 等少数爆款电脑类商品；大部分商品集中在 100‑200 价位。
3. **订单趋势层面**：每日订单波动大，存在明显高峰低谷，可以作为回归测试的监控指标。
4. **数据质量层面**：本次校验暴露出真实业务 BUG，**订单主表和明细金额不一致**。体现只做页面功能测试不足以发现这类问题，测试必须增加数据库层一致性校验，拦截页面显示正常，但底层数据错乱的缺陷。

### 六、测试工作启发

1. 执行下单、改价、优惠等核心业务用例，操作完成之后，不能只看页面，需要 SQL 校验数据库多表数据；
2. 版本上线前后，统计用户注册、订单数量、销售额，对比指标变化，及时发现业务故障；
3. 重点校验主表‑明细表数据一致性，这类 BUG 页面很难发现，但会直接影响财务对账。
